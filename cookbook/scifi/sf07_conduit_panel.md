# sf07_conduit_panel - Conduit panel

_Category: scifi. Open the graph: `cookbook/scifi/sf07_conduit_panel.ptex`._

An interlocking pipe/conduit panel: curved copper pipes weaving across a dark gunmetal panel, standing proud of the surface as raised tubes. This is the first cookbook material to use the `truchet` node, a topology voronoi and perlin cannot make.

## Recipe

`truchet` with `shape=1` (Circle) tiles quarter-circle arcs that always meet edge to edge, so the field it outputs reads as one continuous network of curving pipe paths rather than a scattered or gridded pattern. `size=4` sets the tile density; kept modest so the pipe runs are chunky enough to be legible as tubes rather than a fine weave. The Line alternative (`shape=0`) was considered for a maze/circuit look but rejected: sf03 already owns that flat etched-trace territory, and the brief calls for pipes with real 3D relief, which the Circle shape's continuous curves suit better than Line's right-angle segments.

A single truchet field drives both albedo and relief, so this recipe needs no `blend` at all: `colorize_albedo` thresholds it directly into dark gunmetal panel (below the pipe) and bright copper pipe color (above), using a narrow 0.46-0.50 transition band for a clean edge. Even though there is no blend/opacity mask to protect here, the recipe still keeps a dedicated `colorize_relief_mask` node (a hard 0/1 threshold at the same 0.48-0.52 band) rather than feeding `colorize_albedo`'s own color output into `normal_map`. This mirrors the sf03 lesson (never let one colorize double as both a color source and another node's opacity/height driver) one level further upstream: a future edit to the pipe color gradient can never accidentally reshape the pipe relief, because the two are structurally independent nodes fed from the same layout.

Relief: `normal_map` reads the hard mask with `param4=0` (the flat-normal fix, since the mask is directly-fed and analytic, not a buffered node) and `param1=0.7` for pronounced tube-like relief. Roughness comes straight off the truchet field too (no mask needed, a continuous ramp is fine for a roughness gradient): panel matte, pipe polished. Metallic is a single flat scalar (0.6) on the Material node rather than a routed texture, since both panel and pipe are metal here (no paint-vs-metal split to make, unlike the painted-metal cookbook set).

## Difference from sf03_circuit_board

sf03 is flat etched PCB traces: a `pattern` Square wave gives right-angle stripes with no tile-based curve topology, and its relief is limited to the shared flat-normal fix (no raised geometry, traces read as printed, not extruded). sf07 is the opposite silhouette: `truchet`'s Circle tiles give continuously curving pipe paths, and the relief is deliberately pronounced (`param1=0.7` vs sf03's `0.15`) so the pipes read as physically raised tubes above the panel, not a flat printed pattern.

## Subgraph structure

Grouped per the "Grouping into subgraphs" lever in `docs/AUTHORING.md`:

- **Conduit Pattern** - `ConduitLayout` (truchet), `ConduitColor`, `ConduitMask`. Exposed: `Conduit density` (`ConduitLayout`'s `size`), `Conduit color` (`ConduitColor`'s gradient).
- **Surface Finish** - `PanelRoughness`, `ConduitNormal`. Exposed: `Surface sheen`, `Relief strength`.

`ConduitLayout` feeds all three colorize nodes directly (the single-upstream-node-feeds-multiple-groups case already used in sf01/sf03/sf04), which produces extra boundary output ports on it once Conduit Pattern and Surface Finish are split into separate groups; that is expected, not a wiring bug.

## Concerns / not rendered

This recipe was authored and validated (0 validator errors, Material albedo/roughness/normal ports all wired) but NOT rendered -- no Godot render was run for this task, per the controller's render-and-verdict workflow. The exact numeric range and edge sharpness of truchet's output field is unconfirmed by eye; the 0.46-0.52 threshold band and `param1=0.7` relief strength are defensible starting values reasoned from the node's declared Line/Circle enum and this cookbook's existing threshold conventions, not a value tuned against a real render. If a render later shows the pipe/panel split landing at the wrong ratio or the relief reading too flat/too extreme, retune the threshold band and `param1` first.
