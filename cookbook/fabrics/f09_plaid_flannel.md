# f09_plaid_flannel - Plaid flannel

_Category: fabrics. Open the graph: `cookbook/fabrics/f09_plaid_flannel.ptex`._

A muted brick-red and navy plaid crossing grid over a heather-cream base,
soft matte roughness, and a relief that reads as pressed flannel nap
rather than sharp thread crossings.

## Recipe

Clones `crocodile_skin` like the rest of this category, but instead of
keeping `voronoi_0` as a raw voronoi (every other builder in this file's
lever) it retypes the base generator to `fbm` with `noise=4` (Cellular 3,
"woven crosshatch grid" per `docs/AUTHORING.md`'s noise vocabulary table).
This is the key structural difference from every other material here: the
crosshatch grid `fbm` produces on its own IS the plaid pattern, not a
woven simulation dressed up in plaid colors.

Getting a legible grid took two failed passes, not a lucky first guess.
Read the tracked `quality/cookbook/noise-gallery/fbm_4_cellular3` swatch
(same `noise`/`iterations`/`persistence`, a plain 0-black/1-white ramp)
with `quality/pngread.py` and histogrammed it: the value distribution is a
narrow bell curve centered on ~0.5, not spread evenly across 0..1. A naive
3-stop albedo ramp at the noise-gallery swatch's own coarse scale (4) let
the stripe color sitting on that peak swallow about 70% of the render. A
tight plateau gradient fixed the red-dominance but, at that same coarse
scale, made the low-value crossing regions read as isolated blobs (closer
to a cow-print) rather than a connected grid, since each crosshatch valley
occupies a large fraction of its own coarse cell. The fix was scale, not
more gradient tuning: raising `scale_x`/`scale_y` from 4 to 10 makes each
crossing valley a proportionally smaller slice of its cell, so the same
plain 3-stop ramp (`0.0` deep muted navy, `0.5` muted brick-red, `1.0`
heather-cream) now reads as thin bands connecting into a grid instead of a
spot per cell. Same move `l07_pebbled_leather` made on its own `fbm`
retype, for the same reason: a noise-gallery swatch tuned to keep one
basis legible per diagnostic tile is not tuned for how that basis should
read at material scale.

Relief went through its own iteration. The first pass followed the
brief's suggested LOW `normal_map` `param1` (0.15) for a soft brushed nap
and, on review, read as too flat: the crosshatch barely showed under
lighting. Raised to `param1=0.42`, comparable to `f03_canvas_burlap`'s
coarse-thread relief, moderate rather than sharp, so the grid now reads as
visible relief on lit surfaces while staying well short of a hard-relief
material like stone. `param4=0` (the standing flat-normal fix for a
directly-fed analytic generator) stayed set throughout both passes.

Roughness is a soft, low-contrast matte ramp (0.82 to 0.92), no sheen
split between the grid and the cell interior, unlike `f05_silk_satin`'s
anisotropic sheen chain.

## Distinguishing it from f07/f08

`f07_herringbone_tweed` and `f08_donegal_tweed` are both built on `weave2`
retypes (plus, for f08, an independent overlay voronoi for its color
flecks): the pattern comes from simulating a woven structure and then
recoloring it. This material does not simulate a weave at all. `fbm`
Cellular 3's own crosshatch grid, at the right scale, already looks like
a plaid check on its own; the base generator's native output is the
pattern, with no weave-family retype and no overlay layer involved. It is
the first material in this category built on a noise-vocabulary basis
rather than a structural weave node.

## Subgraph structure

Grouped per the "Grouping into subgraphs" lever in `docs/AUTHORING.md`,
via the same shared `_group_weave_family` helper `f03`-`f08` use (this
donor carries no `blend` node, so no port-source tracing applies).
Opening the graph shows 2 top-level groups (plus `Material` and the
untouched metallic `NonMetallic`) instead of the raw 6-node graph:

- **Plaid Pattern** - `PlaidGrid` (retyped to `fbm`, `noise=4`,
  `scale_x=10`, `scale_y=10`, `folds=0`, `iterations=3`,
  `persistence=0.5`) and `PlaidColor` (the navy/brick-red/cream plaid
  albedo). `PlaidGrid` also feeds **Surface Finish**'s normal and
  roughness colorizes directly, the same shared-upstream-node shape the
  rest of this category's materials use. Exposed: `Check size`
  (`PlaidGrid.scale_x`), `Plaid color`.
- **Surface Finish** - `PlaidHeight` (normal source, the donor's plain
  0-black/1-white ramp, unmodified), `FlannelRoughness` (soft matte
  finish), `PlaidNormal` (`param1=0.42`, `param4=0`, for moderate but
  legible crosshatch relief). Exposed: `Roughness`, `Relief strength`.
