# t09_rippled_wet_sand - Rippled wet sand

_Category: terrain. Open the graph: `cookbook/terrain/t09_rippled_wet_sand.ptex`._

Fine, dense, dappled wet beach sand -- the first cookbook material built on `wavelet_noise` (zero prior use in the cookbook before this).

## Recipe

Built from scratch (no donor has this topology) via `_from_scratch_noise_material`, then the placeholder `perlin_0` is `retype()`d to `wavelet_noise` -- the same move `t07_forest_floor` uses to swap in `fbm`; output port 0 is a plain `f` scalar on both node types, so the swap is connection-safe.

`noise_gallery.py` labels this node "banded wavelet -> ripple/interference", but the actual rendered `wavelet_banded` swatch (`docs/images/noise-gallery/cross-family.png`) at the brief's exact starting params (type=4, scale 4/4, iterations=3, persistence=0.5, frequency=1) is not parallel ripple lines -- it's a fine, dense, dappled mottle, closer to sea-foam or wet-sand grain than literal banding. This recipe leans into what the swatch actually shows rather than forcing a false "ripple lines" claim: `scale_x`/`scale_y` raised from 4 to 10 and `frequency` raised from 1 to 1.6 (the two levers the brief sanctions tuning) for a TIGHTER, denser version of the same dappled character. `type` (4, "Mult 3"), `iterations` (3), `persistence` (0.5), and `offset` (0) are all left at the brief's exact starting values. `scale_x` and `scale_y` are kept equal -- the swatch gives no evidence this node's scale pair controls directionality the way `noise_anisotropic` (a different node) does, so no anisotropy was invented.

Palette is darker and cooler than `t01_sand_dunes`' warm dry-dune tan, roughness is LOW (0.15) for a wet sheen versus dune's high matte roughness, and the grain is fine and dense rather than dune's broad rolls. Not based on any voronoi-plate/`dry_earth` donor, so it doesn't add to that already-overused family either.

Roughness is fed as a flat texture (`WetSandRoughness`, a constant-gradient colorize) rather than left as a Material-node scalar only -- the same lesson `_dry_earth_plates` and `p01_glossy_plastic` (`cookbook_plastics.py`) already established -- so an ORM map exports for the wet-sheen preview instead of silently having none. `RippleNormal`'s `param4=0` is the project's standing flat-normal fix (the wavelet field feeds it directly, the same analytic-generator trap every from-scratch/donor recipe has to correct for).

Not rendered as part of this build pass -- the controller renders for the visual verdict. If the render reads as too smooth/cloudy rather than tightly dappled, `RippleField`'s scale/frequency (exposed as `Ripple scale`, though only `scale_x` moves) are the first levers to raise further; if it reads too glassy/uniform, `Ripple relief` (`RippleNormal.param1`, currently 0.4) is the next lever.

## Subgraph structure

Grouped per the "Grouping into subgraphs" lever in `docs/AUTHORING.md`, the exact `p01_glossy_plastic` (`cookbook_plastics.py`) template for a from-scratch, no-donor material: `RippleField` (the retyped `wavelet_noise`) feeds all three downstream nodes (`WetSandColor`, `RippleNormal`, `WetSandRoughness`), so it has to live in one of the two groups; folding it into the color group avoids a degenerate single-node "finish" group.

- **Ripple Color** -- `RippleField`, `WetSandColor`. Exposed: `Sand color` (`WetSandColor.gradient`), `Ripple scale` (`RippleField.scale_x` only -- nudging it introduces anisotropy since `scale_y` stays fixed).
- **Wet Sand Finish** -- `RippleNormal`, `WetSandRoughness`. Exposed: `Roughness` (`WetSandRoughness.gradient`), `Ripple relief` (`RippleNormal.param1`).
