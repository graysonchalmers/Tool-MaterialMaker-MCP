# m03_brushed_titanium - Brushed titanium

_Category: metal. Open the graph: `cookbook/metal/m03_brushed_titanium.ptex`._

Prompt: "brushed titanium". Added 2026-09 to the noise-vocabulary sweep as a
proof case for `noise_anisotropic`: a directional hairline finish that
`m02_brushed_aluminum`'s warp-stretched perlin cannot match natively, so the
two brushed metals stay clearly distinct rather than one being a recolor of
the other.

## Recipe

`m02_brushed_aluminum` gets its grain by cloning `wood` and straightening a
warp-stretched perlin. Titanium instead starts from `noise_anisotropic`
directly: it is purpose-built for x-axis-interpolated directional noise, so
a high `scale_y`:`scale_x` ratio (48:4) IS the streak, no warp node needed.
The result reads finer and more uniform than aluminum's streak, which is the
point of picking this node.

Built from scratch (no donor topology to clone) via
`_from_scratch_noise_material`'s perlin skeleton, then `retype`d to
`noise_anisotropic` in place -- both nodes expose a single "f" output on port
0, so every downstream connection (albedo, roughness, normal) stays valid
across the swap:

- cool, darker titanium albedo with a faint violet cast (both R and G lean
  toward B) instead of aluminum's neutral bright silver, so the two metals
  read as different alloys, not different lighting on the same one;
- whole surface is metal, so `metallic=1` is a scalar (same reasoning as
  m02: no paint layer to mask off, nothing to wire);
- roughness is a texture, not m02's flat scalar: a second colorize fed by
  the same anisotropic noise so the sheen varies faintly along the brush
  direction for a more realistic brushed look;
- the anisotropic noise also feeds `normal_map` for the fine directional
  groove relief; `param4=0` keeps it a real, if subtle, buffered normal
  rather than the dead-flat default the analytic generator would otherwise
  produce.
